# task26100204

学业风险规则的改权影响追溯库（Go，纯进程内存，由上层直接调用）。

## 功能

- 固定一个学期，学生以 ID 唯一标识；支持新增学生、完整替换风险事实、发布新权重。
- 风险事实：GPA、出勤下降百分比、期中 D/F/W 门数、是否有助学金、是否第一代大学生。
- 初始规则 25/20/15/10/10；每次发布同时指定五个权重（0-50 整数），立即生效。
- D/F/W 项封顶 45、总分封顶 100、分档 0-30/31-60/61-100（边界包含）始终固定。
- 每次发布产生一份不可变、独立标识的影响报告：新旧权重、当时总数、新旧各档人数、
  九种档位迁移人数；新旧规则作用于发布当时完全相同的学生集合与事实。
- 全部历史报告永久可查；按报告查询学生返回当时事实、旧新得分与档位，
  晚于报告新增的学生明确返回 `InCohort=false`。

## API

```go
s := risktrace.NewStore()
s.AddStudent("stu-1", risktrace.Facts{GPA: 1.8, AttendDropPct: 25, MidtermDFW: 2, FirstGen: true})
s.ReplaceFacts("stu-1", risktrace.Facts{GPA: 3.2, HasAid: true})
rep := s.Publish(risktrace.Weights{GPA: 30, Attend: 20, Midterm: 15, NoAid: 10, FirstGen: 10})
got, ok := s.Report(rep.ID)
ex := s.Explain(rep.ID, "stu-1")
```

## 设计要点

- 计分只依赖五个离散分量，将学生按签名（4 个布尔位 + 封顶后的门数，共 752 种）聚合计数，
  发布时按签名组计分，避免逐人重算；`score` 与签名计分共用同一实现保证一致。
- 每名学生保存按操作序号升序的事实版本链，报告记录产生时的序号，
  历史解释通过二分查找定位当时版本，历史报告不受后续替换影响。

## 测试与性能验证

```sh
go test ./...          # 正确性：对照重算、阈值/零权重/两层封顶/档位边界、报告不可变性
go run ./cmd/perfcheck # 规模验证：20 万学生，10 万替换 + 1 万发布 + 10 万查询
```

实测（Apple Silicon）：总耗时约 0.13s（上限 15s），峰值内存约 55 MiB（上限 256 MiB），
最早/中间/最新报告均可准确查询。
